# 予定と報告

明日の予定は`runs/<日付>-plan.md`、朝の報告は`runs/<日付>-report.md`に書き、同じ本文をスレッドに返す。
同日の再実行は、時刻付きの見出しで追記する（例：`# 10/14 18:00 明日の予定`）。
予定は最後の見出しのものを有効とする。

## 書き方

IssueとPRにはリンクを付ける。
予定の候補Issueは`[<Issueタイトル>](<URL>)`、朝の報告のIssueとPRは番号付きリンクで示す。
別リポジトリの番号には`<owner>/<repo>`を添える。

案件は`sources[].name`と、`umbrella`から親をたどった最上位のIssueで特定する。
案件名は親Issueのまとまりや依頼時の短い呼び名を使い、親Issueがあればリンクする。

## 明日の予定

明日着手できる新規起動の候補を、予定の優先順で1候補1行にする。

| 案件名（任意） | 候補Issue                                                              | やること                             |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------ |
| ルール整備     | [標準例外の直接throwを検出する](https://github.com/org/pay/issues/135) | 違反メッセージで置き換え先へ誘導する |

候補Issueには正式なIssueタイトルをリンク付きで書く。
案件名がなければ「—」とする。
やることは任せるか判断できる短い説明にし、積み先PRがある場合はそのリンクと積む理由を添える。
候補はこれから任せる仕事に絞り、完了済みの項目、既存workerの進捗、PRレビュー依頼、台帳更新は朝の報告で扱う。

着手可否を決める問い（`question`のある`needs_decision`）は、表の前の`## 先に聞きたいこと`に置く。
Issueのリンク、問い、推奨、選択肢を1〜2文で書き、回答まで着手を待つことを伝える。
問いは予定の優先順で`limits.max_questions_per_plan`件まで載せ、残りは次の予定に回す。

候補も問いもなければ「明日着手できる候補はありません。」だけで終える。
承認の扱いは[承認](launch.md#承認)に従う。

## スレッドでのやりとり

候補がある場合は、予定の末尾に「全部OK」「#131 だけやめて」「2つだけ」などの返し方と、承認した仕事を翌朝5:00に始めることを添える。
`no_reply: true`の日は、承認の返事がなくても予定どおり起動することと、取り消しの返し方を伝える。

返事への応答は、承認・取り消し・追加・除外の結果を数文で返す。
量が曖昧なら件数を聞き、追加分にはOKを求める。

| 返事            | 応答例                                       |
| --------------- | -------------------------------------------- |
| #134 だけやめて | #134を取り消し、残りを翌朝始めることを伝える |
| 今日は多め      | 何件にするか聞く                             |
| あと1つ         | 追加するIssueと成果物を示し、OKを求める      |

## 退勤予定

[今日の予定登録](schedule.md#今日の予定登録)の結果を数文で返す。

| 結果     | 伝えること                                                              |
| -------- | ----------------------------------------------------------------------- |
| 時刻確定 | 今日の確認時刻と、変更や休みの返し方                                    |
| 時刻不明 | 退勤時刻か休みを尋ねる。返事がなければ17:00に予定を作り、翌朝に起動する |
| 休み     | 今日は予定を作らないこと                                                |

## 朝の報告

直前の予定の項目と、前回の報告以降に結果や確認事項が変わった項目を、1項目1行にする。
取り消した項目を除き、確認事項あり、停止、それ以外の順に並べる。

| 案件名（任意） | Issue | ステータス | 補足 | 作成PR | 確認事項 |
| -------------- | ----- | ---------- | ---- | ------ | -------- |

| 列         | 内容                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------------- |
| 案件名     | 親Issueのまとまりや依頼時の短い呼び名（「自動マージ」など）。親Issueがあればリンクする。全行で不要なら列を省く |
| Issue      | 対象Issueへの番号だけのリンク                                                                                  |
| ステータス | 下表の3種類。台帳の`status`とは別の表示                                                                        |
| 補足       | 停止の主因や暫定判断など、要点1つを40字程度で。予定どおり完了なら「—」                                         |
| 作成PR     | 作成したPRへの番号だけのリンク                                                                                 |
| 確認事項   | 人への問いや操作依頼と推奨を60字程度で。完了した項目も確認があれば記載                                         |

空欄は「—」とする。
表だけでは判断に必要な条件や選択肢を伝えきれない場合に限り、`## 確認の詳細`へIssueのリンクと追加の根拠を書く。
作業経緯は参照先に任せ、表には現在の結果と必要な対応を示す。

| ステータス | 意味                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 完了       | Draft PRを作成し、同じheadで独立レビュー合格、必須検証とCI成功を確認した |
| 未着手     | 今回は開始しなかった                                                     |
| 停止       | 着手したが完了まで進められなかった                                       |

完了の到達点は[task-worker](../../task-worker/SKILL.md)に従う。
人の承認だけを待つ必須チェック（保護されたworkflowの変更承認など）は、人の操作で解消するため、ほかの条件を満たせば完了とし、承認の依頼を確認事項に書く。
レビュー・検証・暫定判断はworkerの最新の最終回答、PR headとCIはGitHubで確かめる。
補足には未着手・停止の原因や不足する確認を示し、実際に進行中ならその事実を書く。
OKなしで閉じた`planned`は承認なし、OK済みで閉じたものは起動枠なしとして扱う。

確認事項の選び方は次のとおり。

- 暫定判断は、その方針でよいかを聞く。
- Issueの残作業や別の課題は、次の予定に載せるかを聞く。
- 新たに`needs_decision`へ移った`question`のない項目は、必要な操作と結果の返し方を示す。
  `question`のある問いは予定で扱う。

項目に結び付かない問題（前回実行の残り、読めないitem、発見上限、指示らしい文、Scheduled Taskの失敗）は、末尾の`## そのほか`に短く書く。

```markdown
# 10/15 朝の報告

| 案件名 | Issue | ステータス | 補足 | 作成PR | 確認事項 |
| --- | --- | --- | --- | --- | --- |
| 決済の再送 | [#131](https://github.com/org/pay/issues/131) | 完了 | 通知先が未確定のため暫定で省略 | [#141](https://github.com/org/pay/pull/141) | 通知は省略でよいか（推奨） |
| — | [#134](https://github.com/org/pay/issues/134) | 未着手 | 起動枠なし | — | — |
```
