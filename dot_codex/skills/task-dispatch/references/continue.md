# 既存workerへの続行

人の判断を待たずに続行できるworkerを対象とし、OKは不要とする。
[PRのある項目](item.md#prのある項目)には送らない。

| 理由    | 条件                                                                                                          | ref                                                                           |
| ------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| stopped | `running`で、worker_threadの最新turnが人の判断を求めない最終回答で止まっている（CIの失敗での停止など）        | なし                                                                          |
| resume  | `needs_decision`から再判定で`ready`になり、`worker_thread`に値がある（[起動の確認](launch.md#起動の確認)の1） | 再判定のきっかけにしたコメントのID、Issueの更新時刻、またはメモに追記した時刻 |

送信履歴は`attempts`の`continue_sent`だけを使う。
種類が変わる前の送信は、下の表の2〜4行目で数えない。
変わる前の送信とは、最後にworkerへ伝えた種類（下の続行の書き方で決める）が今の`kind`と違う間のすべての送信と、noteに`種類=`がある最新の`continue_sent`より前の送信をいう。
次の表を上から当てはめ、最初に当たった行に従う。
早朝の実行は表の扱いに従う。
朝の実行は、理由`stopped`だけを表の扱いで送る。
予定作成では送信せず、「送る」に当たるものを見込みとして載せる。

| 行  | 状況                                                                                 | 扱い                                                                                                        |
| --- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 1   | workerの最新turnが進行中                                                             | 送らず、次の続行を送る実行に持ち越す                                                                        |
| 2   | 同じ理由・同じrefの`continue_sent`があり、その送信より後にworkerのturnが終わっている | 送らない。送っても進まなかったものとして`needs_decision`にし、止まった位置と送った内容を`next_action`に書く |
| 3   | 同じ理由・同じrefの`continue_sent`があり、その送信より後のturnがない                 | 送らない。届いていない可能性があるため`needs_decision`にし、Appで確かめる内容を`next_action`に書く          |
| 4   | 同じ理由の`continue_sent`が、最後の`launched`の後に`limits.max_continues`件ある      | 送らずに`needs_decision`にし、繰り返し止まった位置を`next_action`に書く                                     |
| 5   | 上のどれでもない                                                                     | 送る                                                                                                        |

送るときは、先に`attempts`に`continue_sent`を追記してファイルへ書く。
その後、`codex_app__send_message_to_thread`の`threadId`に`worker_thread`を指定して送る。
同じ項目に複数の理由があれば1通にまとめ、`continue_sent`は理由ごとに書く。
送信が受理されたことを確かめられなければ（エラー・タイムアウトを含む）再送しない。
`failed`を記録して`needs_decision`にし、Appで送信の有無を確かめる内容を`next_action`に書く。

`resume`を送ったら`running`にし、`status`を記録する。
messageの先頭に`$task-worker`を置き、理由・refを自分の言葉で書く。
[決めたことのメモ](launch.md#決めたことのメモ)があれば、その絶対パスも書く。
最後にworkerへ伝えた種類が今の`kind`と違う項目には、今の種類の到達点も書き、`continue_sent`のnoteに`種類=<kind>`を足す。
最後に伝えた種類は、最後の`launched`より後で最新の`種類=`（直後に送信の`failed`があるものは除く）、なければ`requests/<file>.json`の`completionTarget`（`implementation`なら調査）で決める。
調査になった項目には[調査の進め方](../../task-worker/references/research.md)の絶対パス、実装になった項目には調査の進め方を使わず`draft_pr`まで進めることを書く。
同じtaskIdでは`harnexus-crew`が既存workerを返し、到達点を起動し直せないため。
回答の文面は転記せず、workerがGitHubから読む。
