# 日程とスレッドの管理

朝の実行・退勤予定の実行、退勤時刻・休みへの返事、予定の登録・終了時に読む。

## 前日以前の後始末

朝の実行は、報告を書く前に前日以前の分を片付ける。

1. 前日以前の`days/<日付>.yaml`に残っているIDを片付ける。
   `plan_task`は`automation_update`で削除する。
   `plan_thread`と`launch_thread`は`set_thread_archived`でアーカイブする。
   操作はその場で行い、削除・アーカイブ済みと確認できたIDだけ空にする。
   結果が不明なら、次の試行前に対象の状態を読み取る。
2. 使われていない`planned`（追加分を含む）をすべて`plan_cancelled`（note：持ち越し）で閉じる。
   OKのないまま早朝の実行を過ぎた項目は始めず、次の予定に載せ直す。
   有効なOKは残るため、次の予定で聞き直さない。

後始末の失敗は`runs/<日付>-maintenance.md`に操作・ID・理由を残す。
今日の予定作成や返事に影響し、ユーザーの操作が必要な場合だけ、朝の報告に必要な対応を書く。

## 今日の予定登録

退勤予定の実行は、その日の退勤予定を決めて予定作成の実行を登録し、決めた時刻をスレッドで伝える。
Calendarを使うかは`config.yaml`の`calendar.enabled`で決める。

1. 退勤予定を次の表で決める。
   Calendarがオンなら、Calendarのプラグインで今日の予定を一度だけ読み、上の行から順に当てはめる。

   | Calendar | 今日の予定                               | `leave_at`                  | 予定作成の実行の時刻             | スレッドに書くこと               |
   | -------- | ---------------------------------------- | --------------------------- | -------------------------------- | -------------------------------- |
   | オン     | 終日の不在（outOfOffice）                | `off`                       | 登録しない（手順2を飛ばす）      | 今日は予定を作らないこと         |
   | オン     | `calendar.leave_title`と同じ名前の予定   | その開始時刻                | 退勤予定の1時間前                | その時刻                         |
   | オン     | その日の終わりまで続く不在（午後の半休） | 不在の開始時刻              | 退勤予定の1時間前                | その時刻                         |
   | オン     | どれもない（午前だけの不在を含む）       | 空（返事待ち）              | `schedule.plan_at`。返事で動かす | 退勤時刻を聞く                   |
   | オフ     | 読まない                                 | `schedule.plan_at`の1時間後 | `schedule.plan_at`。返事で動かす | その時刻と、返事で変えられること |

2. 予定作成の実行を表の時刻（過ぎていれば10分後）に`$task-dispatch 予定`で登録する。
3. `days/<日付>.yaml`を書く。

```yaml
leave_at: "17:30"     # 退勤予定。休みはoff、返事待ちは空
plan_task: ""         # 予定作成の実行のScheduled TaskのID
plan_thread: ""       # 予定のスレッドのID
launch_thread: ""     # 早朝の実行のスレッドのID
no_reply: false       # 退勤時刻を聞いたが、予定作成の実行の時点で返事がなかった日はtrue
amount: ""            # 量について言われた内容を短く。なければ空
```

予定作成の実行・早朝の実行・朝の実行・返事への対応は、日付をまたいでも、退勤予定の実行で次の日のファイルが作られるまでファイル名の日付が最新の`days/<日付>.yaml`を使う。

予定作成時に`leave_at`が空なら、`no_reply: true`を書いて予定を作る。
早朝の実行での承認の扱いは[返事がなかった日](launch.md#返事がなかった日)に従う。

### 退勤予定のスレッドへの返事

| 返事     | すること                                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 退勤時刻 | その1時間前（過ぎていれば10分後）に予定作成の実行を登録し、`leave_at`・`plan_task`を書いて、時刻を返す。予定作成の実行が登録済みなら時刻を動かす |
| 休み     | `leave_at: off`を書き、登録済みの予定作成の実行があれば消す                                                                                      |

### 報告のスレッドへの返事

| 返事                                                              | すること                                                                                      |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Appで確かめた結果（起動・送信が実際に行われたか、workerがないか） | 結果に合わせて台帳の項目を直し、`status`を変えたら記録する                                    |
| 報告の内容への問い                                                | 台帳とGitHubから説明する                                                                      |
| 調査を終えた項目を実装へ進めるかの答え                            | [仕事の種類の指定](launch.md#okの受け取り方)と同じに扱う。進めないなら`next_action`にそう書く |

### Scheduled Taskの扱い

予定作成の実行は、その場で`automation_update`を呼び、`kind: cron`の単発タスクとして登録する。
Claudeでは`mcp__codex_link__automation_update`と`mcp__codex_link__set_thread_archived`を使う。
この経路で作った単発タスクは、別のClaudeスレッドからもIDで更新・削除できる。
ツールが使えないときは、該当する操作を失敗として記録する。

Appの`list_projects`で`~/agent-desk/`のプロジェクトIDを確かめる。
登録時のモデルと思考量は`~/.config/harnexus/models.json`の`skills.dispatch`から読む。
Claudeのツールでは`runSettings`に`model`と`reasoningEffort`を渡す。
同じ`runSettings`で`target`に`type: project`と`projectId`を、`executionEnvironment`に`local`を指定する。
時刻を更新するときは、登録済みの設定を読み、時刻以外の値を保つ。

- 作る前に`plan_task`を見て、IDがあれば作らずに時刻を更新する。
  作ったらツールが確定したIDをすぐ書く。
  作成の結果が分からなければ作り直さず、`## そのほか`に書き、Appで確かめるよう伝える。
- 予定作成の実行は繰り返し回数を1回に設定する。
  予定を書き終えたら、次の朝の実行に削除を任せるため、`plan_task`を残す。
  手動で予定を作った時点で、その日の予定作成がまだ予約されていれば取り消す。
  時間を過ぎても、自分のスレッドのIDは記録する。
  lockを取れなかったときは、自分の時刻を10分後へ移して終了する。

### スレッドの扱い

予定のスレッドは、自分のスレッドのID（`CODEX_THREAD_ID`）を`plan_thread`に書き、ユーザーの返事を待つ。
起動は早朝の実行が行うため、予定のスレッドは自分ではアーカイブせず、次の朝の実行が[前日以前の後始末](#前日以前の後始末)でアーカイブする。
早朝の実行は、自分のスレッドのIDを`launch_thread`に書く。
結果は朝の報告で伝えるため、早朝の実行のスレッドも同じ後始末でアーカイブする。
