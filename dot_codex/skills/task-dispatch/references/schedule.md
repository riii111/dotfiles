# 日程とスレッドの管理

朝の段取り、退勤時刻・休みへの返事、予定の登録・終了時に読む。

## 1日の段取り

報告の回は、報告を書く前にその日の退勤予定を決めて予定の回を登録する。
Calendarを使うかは`config.yaml`の`calendar.enabled`で決める。

1. 前日以前の`days/<日付>.yaml`に残っているScheduled Taskを`automation_update`で消し、予定のスレッドをアーカイブして、どちらも空にする。
   ただし前日が`no_reply: true`なら、そのスレッドは残し、次の朝にアーカイブする（何を始めたかをユーザーがそこで確かめるため）。
2. 使われていない`planned`（追加分を含む）をすべて`plan_cancelled`（note：持ち越し）で閉じる。
   OKのないまま翌朝になった項目は始めず、次の予定に載せ直す。
   有効なOKは残るため、次の予定で聞き直さない。
3. 退勤予定を次の表で決める。
   Calendarがオンなら、Calendarのプラグインで今日の予定を一度だけ読み、上の行から順に当てはめる。

   | Calendar | 今日の予定 | `leave_at` | 予定の回の時刻 | 報告の冒頭 |
   | --- | --- | --- | --- | --- |
   | オン | 終日の不在（outOfOffice） | `off` | 登録しない（ここで終える） | 書かない |
   | オン | `calendar.leave_title`と同じ名前の予定 | その開始時刻 | 退勤予定の1時間前 | その時刻 |
   | オン | その日の終わりまで続く不在（午後の半休） | 不在の開始時刻 | 退勤予定の1時間前 | その時刻 |
   | オン | どれもない（午前だけの不在を含む） | 空（返事待ち） | `schedule.plan_at`。返事で動かす | 退勤時刻を聞く |
   | オフ | 読まない | `schedule.plan_at`の1時間後 | `schedule.plan_at` | その時刻 |

4. 予定の回を表の時刻（過ぎていれば10分後）に`$task-dispatch 予定`で登録する。
5. `days/<日付>.yaml`を書く。

```yaml
date: 2026-10-14
leave_at: "17:30"     # 退勤予定。休みはoff、返事待ちは空
plan_at: "16:30"      # 予定の回の時刻
plan_task: ""         # 予定の回のScheduled TaskのID
plan_thread: ""       # 予定のスレッドのID
no_reply: false       # 退勤時刻を聞いたが、予定の回の時点で返事がなかった日はtrue
amount: ""            # 量について言われた内容を短く。なければ空
```

予定・起動・返事の回は、`date`が最も新しい`days/<日付>.yaml`を使う。
日付をまたいでも、翌朝の報告の回が次の日のファイルを作るまでは同じファイルを使う。

予定の回の時点で`leave_at`が空のままなら、返事を忘れている日とみなし、`no_reply: true`を書いて予定を作る。
この日だけは、夜の起動の回の時点でOKのない新規起動も予定どおり始める（[返事がなかった日](launch.md#返事がなかった日)）。

### 報告のスレッドへの返事

| 返事 | すること |
| --- | --- |
| 退勤時刻 | その1時間前（過ぎていれば10分後）に予定の回を登録し、`leave_at`・`plan_at`・`plan_task`を書いて、時刻を返す。予定の回が登録済みなら時刻を動かす |
| 休み | `leave_at: off`を書き、登録済みの予定の回があれば消す |
| Appで確かめた結果（起動・送信が実際に行われたか、workerがないか） | 結果に合わせて台帳の項目を直し、`status`を変えたら記録する |
| 報告の内容への問い | 台帳とGitHubから説明する |

### Scheduled Taskの扱い

Scheduled Taskは、Codexスレッドで使える`automation_update`で作成・更新・削除し、`~/agent-desk/`を作業ディレクトリにする。

- 作る前に`plan_task`を見て、IDがあれば作らずに時刻を更新する。作ったらすぐIDを書く。
  作成の結果が分からなければ作り直さず、`## そのほか`に書き、Appで確かめるよう伝える。
- 予定の回は1回だけ動かす。
  予定を書き終えたら、`plan_task`を消して空にする。
  時間を過ぎても、自分のスレッドの記録と`plan_task`の削除は済ませる。
  lockを取れなかったときは、自分の時刻を10分後へ移して終了する。
- 消せなかったIDは`days/<日付>.yaml`に残し、`## そのほか`に書く。次の朝の段取りで消す。

### スレッドの扱い

予定のスレッドは、自分のスレッドのID（`CODEX_THREAD_ID`）を`plan_thread`に書き、ユーザーの返事を待つ。
返事の回のたびに、その予定と追加分の新規起動の`planned`がすべて決着したかを確かめ、決着していれば最後の返事を返してから自分をアーカイブし、`plan_thread`を空にする。
決着とは、起動した・取り消した・外れた（`plan_cancelled`）のどれかになったことをいう。
新規起動を1件も載せなかった予定と`no_reply: true`の日の予定は、自分ではアーカイブせず、朝の段取りでアーカイブする。
