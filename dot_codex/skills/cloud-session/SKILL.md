# Cloud Session

このチャットの最初のメッセージが `/cloud <ID>` だけなら、このスキルを使わない。
それは harnexus がこのチャットをセッションにつなぎ損ねたものなので、そのことだけを伝える。

1. 新しく始めるか、既存のセッションを引き継ぐかを決める。
   引き継ぐ場合は、対象のセッションのIDか`claude.ai/code`のURLを確かめる。
   分からなければユーザーに聞く。
2. `harnexus cloud`をサンドボックス外で一度実行する。
   `harnexus`が未導入なら、代わりに互換入口の`harnexus-task cloud`を同じ引数で使う。
   対象は今のチャットのプロジェクトになるので、`--project`は付けない。
   ユーザーが別のリポジトリを指定したときだけ、`list_projects`でそのprojectIdを調べて`--project <projectId>`を付ける。
   - 新しく始める：依頼の本文をファイルに保存し、`--prompt-file <そのファイルの絶対パス>`を付ける。
     本文は、ユーザーの依頼をCloudのClaudeがそのまま読める形にまとめる。
   - 引き継ぐ：`--link <IDかURL> --title <短い名前>`を付ける。
   - Codexは`sandbox_permissions: require_escalated`を付け、Claudeはそのまま実行する。
     パイプ・リダイレクト・`cd`などを付けず単独で実行する。
     許可の確認が出たら、ユーザーの承認を待つ。
3. 成功したら、出力のthreadIdのチャットでそのセッションを見られることと、出力のurlを伝える。
   出力に`alreadyLinked: true`があれば、新しいチャットは開かず、すでにつながっているそのチャットを伝える。
   失敗したら再実行せずエラーを伝え、create_threadを直接呼ばない。
   新しく始めたセッションは失敗しても動き続けるので、エラーに出たセッションIDも伝える。

開いたチャットは、最初のメッセージの`/cloud`でセッションにつながる。
そのセッションが別のセッションを始めると、そのチャットも自動で開く。
