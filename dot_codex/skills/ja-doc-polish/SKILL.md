# ja-doc-polish

指定された文章だけを推敲し、事実と結論は変えない。

作業前に `../japanese-tech-writing/SKILL.md` を読み、食い違う点はこのSKILLを優先する。
lintとfmtで直せる点は、そちらに任せる。

READMEやPR説明、回答など、判断や実行に使う文章は要点を先に示す。

## 図で説明する

文章だけでは関係を追いにくい場合は、Mermaidを使う。
1つの図で答える問いを決め、その問いに関わる要素だけ載せる。

| 伝えること       | 図             |
| ---------------- | -------------- |
| 主体間のやり取り | シーケンス図   |
| 状態の移り変わり | 状態図         |
| 処理の流れ       | フローチャート |
| 依存関係         | フローチャート |

処理ややり取りは、きっかけから矢印をたどるだけで主体と動作、条件、順序を追えるようにする。
形ごとに1つの役割を持たせる。
条件やきっかけは、ラベルの文言ではなく対応する形で描く。

| 要素     | フローチャート | シーケンス図     | ラベル |
| -------- | -------------- | ---------------- | ------ |
| きっかけ | 六角形         | 最初のメッセージ | 出来事 |
| 主体     | 長方形         | participant      | 名詞   |
| 動作     | 矢印           | メッセージ       | 動詞   |
| 条件     | ひし形         | alt              | 問い   |

変更の説明で既存の処理も描くときは、主体の名前に「新規」「変更」「既存」を添える。

## 表現を整える

- 表の1つのセルには1つの値だけを書く。
  複数の値が入るなら、行か列に分ける。
- 括弧は略語の正式名など、表記に必要な場合だけ使う。
  その他の補足は本文に組み込み、列挙するなら箇条書きに分ける。
- PRやIssueはタイトルとリンクで示す。
  文書の趣旨に関わらない参照は省く。

## lintとfmt

`~/ghq/github.com/riii111/dotfiles/scripts/ai-docs` を使う。
観点と基準は同じディレクトリの `README.md` にある。
Markdownファイルは直接検査する。
回答文は一時的な `.md` ファイルに書き出して検査し、整えた文章をチャットに返す。
`<ファイル>` は絶対パスで渡す。

```sh
npm --prefix ~/ghq/github.com/riii111/dotfiles/scripts/ai-docs run lint -- <ファイル>
npm --prefix ~/ghq/github.com/riii111/dotfiles/scripts/ai-docs run fmt -- <ファイル>
```

lintの警告を直してからfmtをかけ、最後にもう一度lintを実行する。
警告が残るときは、残した理由を報告する。
検査後に元の文章と照合し、事実や必要な情報を落としていないか確認する。
