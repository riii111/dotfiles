# suggested-issue

Issueの投稿はユーザーがGitHub画面で行う。
このスキルは下書きの作成・校正と、事前入力済みの作成リンクの生成だけを担う。
`gh issue create` やAPIでの起票はしない。

## 提案

- 現在の作業を続け、返答の最後に1行で候補を示す。
  例: `Issue候補: 〇〇の重複処理をまとめたい（起票するなら「Issueにして」と言ってください）`
- 候補は、現在の作業で目にした範囲から挙げる。
  候補を探すための追加調査はしない。
- 後から対応する価値がある別件だけに絞る。
  現在の作業で直すべきもの、些細な表記揺れ、根拠のない推測は挙げない。
- 候補の対応を現在の作業範囲へ加えない。
- 断られた候補は同じ会話で再掲しない。
  未判断の候補を催促しない。
- ユーザーがIssue化を依頼したら、作業の区切りを待たず下書きに進む。

## 下書き

チャットに起票先 `OWNER/REPO`・タイトル・本文を示す。

- 起票先は現在のGit remoteを既定にする。
  remoteに複数のGitHubリポジトリがある場合や、別リポジトリの話題である場合だけユーザーに確認する。
- タイトルは対象と望む変化が分かる1文にする。
- 本文は次の見出しで簡潔に書く。
  後から読む人が会話を知らなくても分かるように、作業中の経緯ではなく事実を書く。

```markdown
## 背景
## 課題
## 期待する状態
```

- 該当箇所は、GitHub上にあるコードならコミットSHA付きのリンクを添えてよい。
  未コミット・未pushの変更はファイルパスと関数名などで示し、存在しないリンクを作らない。
- トークン・パスワード・内部URL・顧客情報などの機密情報を本文に入れない。
  公開リポジトリへ非公開リポジトリのコードや内容を書かない。

## 校正

ユーザーの修正指示を反映した全文を示す。
指示がなくなるまで繰り返す。

## 作成リンク

ユーザーが下書きを確定したら、確定した本文をそのままファイルに書き出し、スクリプトでURLを生成する。

```bash
python3 ~/.codex/skills/suggested-issue/scripts/issue-url.py \
  --title '<タイトル>' --body-file <本文ファイル> [--repo OWNER/REPO]
```

- 出力のJSONの `repo` と `url` を示し、「開いた画面で確認して投稿してください」と添える。
- 終了コード2は起票先を特定できない場合で、候補を示してユーザーに確認する。
- 終了コード3はURLが長すぎる場合で、`url` は出力されない。
  短くした本文の案を示して承認を得る。
  確定済みの本文を無断で切り詰めない。
- 作成リンクを渡した後に修正した場合は、URLを再生成して渡す。
  開いたGitHub画面の内容は更新されないことを伝える。
