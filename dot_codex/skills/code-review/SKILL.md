# code-review

レビューを行う。実装や PR 作成はしない。通知はユーザーまたは呼び出し元が明示した場合だけ行う。外部への投稿・返信・resolve はユーザーの明示許可がある場合だけ行う。

読者は変更を初めて読み、内部実装や調査経緯を知らない。一般的な開発知識は前提にしてよい。

この個人用 SKILL が選択された場合、レビューの採否・重要度・出力形式は本 SKILL に従う。リポジトリ固有の技術・業務規約を根拠として使い、別のレビュー SKILL の出力形式や `[imo]` を除外する指示で置き換えない。

## 調査と判定

[共通レビュー基準](references/review-core.md) を全文読み、その手順・観点・採否基準・検証方針に従う。AIへの修正依頼、または変更の全体像を説明済みの再レビューでは、[ai-code-review](../ai-code-review/SKILL.md) を使う。ai-code-review を使う場合は以降の説明工程を実行しない。再レビューでもユーザーが変更の解説を求めた場合は、本 SKILL の説明工程を使う。

## 説明担当への引き継ぎと出力

本体がレビュー・検証・指摘の採否判断と統合を終えたら、[回答作成の分担手順](compose-response.md) に従う。採用指摘と変更の根拠をまとめ、会話履歴を引き継がない説明担当の subagent に渡す。レビュー観点を分担した担当とは別に起動する。

説明担当が explain-change による説明全文と投稿可能なコメントを作り、本体が引き継ぎ内容と照合してから、一つのチャット回答として返す。説明のための要約で採用指摘を落とさない。

個別指摘への質問など、ユーザーが回答範囲を絞った場合は本体で必要な箇所だけ答える。subagent が利用できない場合は本体で同じ工程を順に実施し、担当を分離できなかったことを短く伝える。
