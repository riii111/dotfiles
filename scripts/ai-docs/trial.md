# 既存SKILLでの試用結果

ローカル環境はNode.js 24.20.0、依存関係は同じディレクトリの`package-lock.json`で固定した。

## 誤検知を見て調整した点

初回は文章250件とリンク11件を検出した。
次の検出は対象外として扱うよう調整した。

| 検出                                                        | 件数 | 調整                                                   |
| ----------------------------------------------------------- | ---- | ------------------------------------------------------ |
| テンプレートの`URL`や`{skill_path}`などを実ファイルと見なす | 11   | このリポジトリの既知の仮のリンク先をリンク検査から除外 |
| `場所: [ファイル名:行番号](URL)`をラベルの羅列と見なす      | 1    | リンク文字内のコロンをラベルとして数えない             |
| 英語だけの文に日本語向けの100字制限を適用する               | 3    | ASCII文字だけの文を文長検査から除外                    |

| ルール                  | 整形前 | 整形後 |

| 文の長さ                |     20 |     20 |

リンク検査の警告は0件になった。
本来のリンク切れを検出できることは、存在しないファイルと別ファイルの存在しない日本語見出しを使ったテストで確かめた。

行内の文数の警告は、ファイル名順の218件から等間隔で40件を抽出し、元の行と照合した。
ほかの文章の警告28件はすべて確認した。
確認した68件では、定めた形の基準に反する明確な誤検知は見つからなかった。
これは全246件の誤検知率ではなく、100字の制限や冗長表現の提案をすべて採用すべきという評価でもない。
コマンド名が多い文など、分割する必要があるかは書き手が判断する。

整形は全53本のコピーで試し、44本に変更が生じた。
全53本で、位置情報と文章内の空白を除いた構文木が一致し、コードブロックの内容も一致した。
全53本で再整形による追加の差分はなかった。
この確認は手順の意味を理解する検証ではないため、実際に適用するときは差分の確認を残す。
既存SKILLの管理元と適用先には、この整形を反映していない。

残った行内の文数の警告11件は、強調やリンクの区切りなどを挟むため、改行の自動修正を控えたもの。
短い2文目が補足として適切かどうかは、機械検査では判断していない。
