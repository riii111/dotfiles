# Markdownの検査と整形

日本語の文章とSKILLの参照を検査し、文の区切りとMarkdownの書式を整える。
読みにくさの兆候を警告し、内容の判断が要らない改行や書式だけを自動で直す。

## 検査する観点

| 観点                     | 困ること                                                       | 検査する基準                                   | 自動修正                       |
| ------------------------ | -------------------------------------------------------------- | ---------------------------------------------- | ------------------------------ |
| 1行に1つの決まりを書く   | 複数の決まりが1行に並ぶと、ソースと差分を追いにくい            | 日本語を含む行は2文まで、2文目は20字以内       | 長い2文目や3文目の前で改行する |
| ラベルを羅列しない       | 「依頼：」「変化：」が並ぶと、文としてつながりを読み取りにくい | 本文の1行に日本語のラベルとコロンが2つ以上     | なし                           |
| 括弧に説明を詰め込まない | 長い条件や例を括弧に入れると、本文と補足を行き来する必要がある | 日本語を含む括弧内が40字を超える               | なし                           |
| 1文を長くしない          | 一度に追う条件や操作が増える                                   | 日本語を含む文が100字を超える                  | なし                           |
| 冗長な表現を減らす       | 「確認を行う」のような言い回しが文を長くする                   | 既存のtextlintルールで冗長な表現を検出する     | なし                           |
| 参照をたどれるようにする | ファイルや見出しを変更した後、手順の参照先が失われる           | ローカルのリンク先ファイルとアンカーが存在する | なし                           |

行内の文数、ラベル、括弧の検査は本文と箇条書きに適用する。
コードブロック、引用、表、先頭のYAMLは、書式例や機械が読む情報を含むため対象外とする。
コード内の句点やリンク先URLは文の区切りとして数えず、リンク文字内のコロンもラベルとして数えない。
リンク検査では、既知のテンプレートの仮の参照先を除外する。外部URLへの通信は行わない。

## 整形で保つもの

文の区切りで改行すると、1つの決まりを直した差分をその行で追いやすくなる。
短い2文目は同じ行に残す。
強調やリンクの途中を分断する改行は警告だけに留める。

表、箇条書き、字下げはPrettierでそろえ、既存の改行とコードブロックの内容を保つ。
整形前後の構文木を比べ、Markdownの構造や空白以外の文章が変わる場合は書き換えを止める。
この確認は手順の意味を理解する検証ではないので、整形後の差分は書き手が確認する。

## 書き手が判断すること

- 短い2文目が前の文の理由・例外・条件を補っているか。別の決まりなら別の行にする。
- 長い文や括弧を分ける必要があるか。警告の基準に達しただけで、読みにくいとは限らない。
- 条件ごとの扱いを表にするか、見出しと中身が合っているか、文書間で指示が重複していないか。
- SKILLの手順や設定項目が正しいか。参照先の存在だけでは、内容の正しさは確かめられない。

## コマンド

Node.js 22以上を使い、リポジトリのルートで実行する。

```sh
npm --prefix scripts/ai-docs ci --ignore-scripts
npm --prefix scripts/ai-docs run lint
npm --prefix scripts/ai-docs run links
npm --prefix scripts/ai-docs run fmt -- --check <file.md>
npm --prefix scripts/ai-docs run fmt -- <file.md>
```

`lint`と`links`の対象は既存SKILL関連のMarkdown。引数でファイルを絞れる。
文章の警告は確認用で、`lint -- --strict`を付けると失敗になる。リンク切れと実行エラーは失敗になる。
`fmt -- --check`は書き換えずに確認し、`fmt -- <file.md>`は指定したファイルだけを整形する。
