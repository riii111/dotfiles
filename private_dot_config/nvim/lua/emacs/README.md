# Emacs 編集モード

Normal モードの `e` で入る、Emacs 風のキーで編集できる Insert モード。
文章を書きながら細かく移動・削除するときに Normal モードへ戻らずに済ませるためのもの。
通常の `i` や `a` で入った Insert モードは何も変わらない。

外部プラグインには依存しない。
`init.lua` の `require("emacs").setup()` で有効になる。

## 開始と終了

- 開始: Normal モードで `e`。挿入位置は組み込みの `i` と同じで、開始時に移動も編集もしない。
- 終了: `Esc` または `C-c`。専用キーは外れ、元のマッピングに戻る。
- 有効な間はステータスラインのモード表示が `EMACS`（GitHub の Emacs Lisp と同じ `#c065db`）になり、カーソルは Normal モードと同じブロック型になる。
- `C-o` で一時的に Normal モードのコマンドを実行しても、Insert モードに戻れば続く。
- 別のバッファやウィンドウへ移ったとき、対象バッファが削除されたときは終了する。戻っても再開しない。
- 対象は `buftype` が空で `modifiable` のバッファだけ。
  ヘルプ、ターミナル、Oil、Telescope などでは `e` は従来の単語末尾への移動のまま。
- Lua からは `require("emacs").start()`、`stop()`、`is_active()` を使える。

## キー

`C-` は Ctrl、`M-` は Alt（Meta）。

| キー | 動作 |
|---|---|
| `C-f` / `C-b` | 次 / 前の 1 文字へ。行をまたぐ |
| `C-n` / `C-p` | 下 / 上の表示行へ（`gj` / `gk` と同じ）。続けて押す間は横の位置を保つ |
| `C-a` / `C-e` | 論理行の先頭 / 末尾へ |
| `M-f` / `M-b` | 次の単語の末尾の直後 / 単語の先頭へ |
| `M-<` / `M->` | バッファの先頭 / 末尾へ |
| `C-d` / `Delete` | 次の 1 文字を削除。行末では改行を削除して次の行とつなぐ |
| `Backspace` / `C-h` | 前の 1 文字を削除。行頭では前の行とつなぐ |
| `C-u` | 行頭からカーソルの直前までを切り取る |
| `C-k` | カーソルから行末までを切り取る。残りが空白だけなら改行まで切り取る |
| `M-d` / `M-Backspace` | `M-f` / `M-b` の移動先までを切り取る |
| `C-y` | 切り取った内容（ふだんは最新のもの）を貼り付け、その直後へ移る |
| `M-y` | `C-y` / `M-y` の直後に押すと、貼り付けた内容を 1 つ前の切り取りに差し替える。最も古いものの次は最新に戻る |
| `C-/` / `C-_` | Undo |
| `C-v` / `M-v` | ほぼ 1 画面ぶん下 / 上へスクロール（Normal の `C-f` / `C-b` と同じく 2 行重ねる） |
| `C-l` | 現在行を画面の中央・上端・下端へ。続けて押すと順に切り替わる。カーソルは動かない |
| `M-r` | カーソルを画面の中央・上端・下端の行の先頭へ。続けて押すと順に切り替わる（`H` / `M` / `L` と同じく、`'scrolloff'` の分だけ内側。本文が画面より短いときの中央は本文の中央） |
| `M-{` / `M-}` | 前 / 次の段落の区切りへ。空白だけの行も区切りとみなす |
| `C-SPC`（`C-@`） | カーソル位置に選択の起点（マーク）を置く。移動するとマークとカーソルの間が範囲として色付く |
| `C-w` | 範囲を切り取る。範囲がなければ `M-Backspace` と同じく直前の単語を切り取る |
| `M-w` | 範囲をコピーする（切り取りの履歴に入り、`C-y` で貼れる） |
| `C-g` | 範囲をやめる。モードは続く |
| `M-h` | カーソルのある段落を範囲にする（前後の区切り行の先頭まで、Emacs と同じ） |
| `M-t` | カーソルのある（または直前の）単語と次の単語を入れ替え、その後ろへ移る。続けて押すと単語を後ろへ送る |
| `M-u` / `M-l` / `M-c` | カーソルから単語の末尾までを大文字 / 小文字 / 先頭だけ大文字にし、その後ろへ移る |
| `M-\` | カーソルの前後のスペースとタブを消す |
| `M-SPC` | カーソルの前後のスペースとタブを 1 個のスペースにまとめる |
| `M-a` / `M-e` | 文の先頭 / 末尾へ |
| `M-k` | 文の末尾まで切り取る |
| `C-s` / `C-r` | 前 / 後ろへ検索（Vim の `/` / `?`）。`Enter` で一致の先頭へ移ってモードに戻り、`Esc` で元の位置に戻る |
| `M-z` に続けて文字 | 次に出てくるその文字まで（その文字を含めて）切り取る。見つからなければ何もしない |

上記以外のキー（`C-o`、`C-r` など）は Vim の Insert モードのまま。
文は `。！？．` か、空白や行末が続く `.!?` で終わり、直後の閉じかっこ・引用符（`」』）】"'` など）までを含む。
段落の終わりも文の終わりになる。段落の中の改行は空白と同じに扱う。
`Mr.` のような略語でも文が終わる（Emacs の `sentence-end-double-space` を切ったときと同じ）。

検索は `i_CTRL-O` から Vim の検索を使うので、入力中の一致の表示（`'incsearch'`）、次の一致へ進む `C-g` / 前の一致へ戻る `C-t`、
空のまま `Enter` で前回の検索の繰り返しが使える。
Emacs と違って、カーソルは一致の末尾ではなく先頭に来る。

範囲は移動するキー（矢印キーを含む）で伸び縮みし、文字の入力やそれ以外の専用キー、モードの終了で消える。
文字を打っても範囲は置き換わらない（Emacs の既定と同じ）。
Vim の `C-g u` など・`C-r`（レジスタの貼り付け）、blink.cmp の `C-SPC`（補完を開く）、nvim-autopairs の `M-e`（fast wrap）は、このモードの間は使えない。
macOS で `C-SPC` が入力ソースの切り替えに使われているときや、ほかのキーにしたいときは、`setup` の引数で変える。

```lua
require("emacs").setup({ set_mark = { "<C-]>" } })
```

Vim の `C-v`（文字をそのまま入力）はこのモードでは使えないので、同じ働きの `C-q` を使う（端末のフロー制御が有効だと `C-q` は届かない）。

## 通常の Insert モードとの違い

- 文字の単位は Normal モードの `l` / `h` と同じ。結合文字や絵文字の連結（ZWJ、国旗、肌の色）はまとめて 1 文字として動き、消える。
  `'delcombine'` は見ない。
- 単語はバッファの `'iskeyword'` で単語文字とされる文字の連続。
  日本語の文字はすべて単語文字なので、ひらがな・カタカナ・漢字・英字が続く部分は 1 語になり、`、` `。` や空白で区切られる。
  形態素での区切りはしない。
- 切り取った内容はこのモジュールだけが持つ。レジスタやシステムクリップボードは読み書きしない。
  新しいものから 60 件まで保持し、バッファをまたいで共有する。モードを終えても残るが、Neovim を終了すると消える。
  `M-y` で差し替えたあとの `C-y` は、差し替えた先の内容を貼る。次に切り取ると最新に戻る（Emacs と同じ）。
- 切り取りを続けて押すと内容をつなぐ。前方への切り取りは後ろへ、後方への切り取りは前へ足し、元の文章の順に保つ。
  間に文字入力・移動・削除・貼り付け・Undo・モード終了など他のキーを挟むと、次の切り取りは新しい 1 件になる。
  何も切り取れなかったときは内容を変えない。
- 専用キーの編集はそれぞれ 1 回の Undo で戻る。直前・直後に打った文字とはまとめない。
  矢印キーと同じく、専用キーで移動すると、その前後に打った文字も別々の Undo になる。
- 補完メニューが開いていても専用キーが優先する。候補を確定せずにメニューを閉じてから動く。
  （blink.cmp のプレビュー挿入を同期的に取り消すため、blink.cmp の内部 API を呼んでいる。blink.cmp の更新時は `tests/nvim/run.lua` で確認する）

### `C-u` は Readline 式

Emacs の `C-u`（universal-argument）ではなく、Readline やシェルと同じ「行頭まで切り取り」にしている。
インデントも含めて、Insert モードを始めた位置より前も切り取る。
行頭では何もせず、前の行の改行は消さない。

## 初版の制限

- 切り取りの履歴は永続化しない。
- `C-x` 系（`C-x C-x` を含む）、`C-t`、`C-o`（open-line）など、上の表にないキーは実装していない。
  `C-x` は Vim の Insert 補完の入口なので、`C-x` で始まるキーを足すと続きのキーを待つ時間が生じる。
- Normal モードの `e` を置き換える。通常のバッファでの単語末尾への移動は `:normal! e` などで行う。
  Visual モードとオペレーター待機（`de`、`ye` など）の `e` は変わらない。
- `e` のカウントは無視する。
- `C-n` / `C-p` は `gj` / `gk` の挙動に従う。行が短いときは行末の後ろ、タブの途中ならタブの前に止まる。
- Markdown を開いたときの自動開始はしない。
- Alt / Meta と `Esc` の区別は端末と Neovim の設定（`'ttimeoutlen'` など）に任せる。macOS の Option を Meta として送る設定は端末側で行う。
- IME は制御しない。対象は確定済みの文字だけで、未確定の入力は OS 側の処理に任せる。

## 無効にする

`init.lua` から `require("emacs").setup()` の行を消す。
起動中に外すなら `:lua require("emacs").teardown()`（Normal の `e` も元に戻る）。

## テスト

実際のマッピングにキー列を流す結合テストが `tests/nvim/emacs.lua` にある。

- プラグインなし: リポジトリのルートで
  `nvim --clean --headless --cmd 'set rtp^=private_dot_config/nvim' -c 'lua dofile("tests/nvim/emacs.lua")({ exit = true })'`
- 全プラグイン込み（blink.cmp、autopairs、lualine との共存を含む）: `scripts/nvim-plugins.py check` の中で `tests/nvim/run.lua` から実行される。

自動では確かめられない次の点は、実際の端末で手動で確認する。

1. `M-f` `M-b` `M-d` `M-Backspace` `M-<` `M->` が Alt / Option で届く（`:verbose imap <M-f>` で専用キーが見え、押して動く）。
2. `C-/` を押して Undo される（端末によっては `C-_` として届く）。
3. `Esc` の直後に `f` などを打っても `M-f` と取り違えない。macOS の Option+Space は Meta として送られないと、`M-SPC` ではなくノーブレークスペースが入る。`M-{` / `M-}`（Option+Shift+`[` / `]`）も届く。
4. 日本語 IME で変換中に `C-n` などを押したときは IME 側の操作になり、確定後の文字だけがこのモードで編集される。
5. ステータスラインに `EMACS` が表示され、`Esc` で消える。
