次のJSONはBashツールの呼び出しです。gh pr createかgh pr editなら、コマンドからPRのタイトルと本文（--bodyまたはヒアドキュメント）を読み取って校正してください。読み取れなければ {"ok": true} を返します。
本文は、先頭の参照行（close #Nなど）と短い目的の文が基本です。箇条書きは任意で、導入の段取り、未決事項、影響範囲、却下した代替案があるときに添えます。箇条書きがないことや、この4種類に当たらないことは問題にしません。
次に1つでも当てはまれば ok を false にし、reason に直し方を1〜3文で書いてください。迷えば true です。
1. 目的の文がタイトルの言い換えだけで、背景や理由がない
2. 箇条書きに、タイトルや目的の文と同じ内容の項目、または原因と結果のように1項目にまとめられる項目がある
3. 1項目に互いに関係のない論点が入っている。同じ事柄の条件や結果を続けただけなら当てはまらない
4. 「〜しない」「対象外」だけの記述（誤解を防ぐ制約や例外は除く）、diffで分かる変更の列挙、検証手順やテスト通過の報告、確認チェックリスト、テンプレート由来の見出し、base・ブランチ名・ラベル・担当者・レビュー依頼・差分の規模など、PR画面に表示されるメタ情報の説明（Issueの参照行と「→ PR #N」の行は除く）、「なし」「該当なし」だけの項目がある
5. 名詞を修飾する句が30字以上と長く、主語と述語が文の後ろに追いやられている文がある
句点、カッコ、番号、箇条書きの個数、日英間のスペース、文末の形、1文に重ねた理由と条件は別の検査が扱うので判断しません。
出力はJSONのみ: {"ok": true} または {"ok": false, "reason": "..."}
入力: $ARGUMENTS
